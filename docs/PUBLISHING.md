# Public documentation and publication boundaries

Publish information that helps people understand, reproduce, evaluate and
contribute to Clearproof: source-backed examples, technical documentation,
release notes, an adoption roadmap and useful project updates.

Keep internal operating plans, budgets, pricing experiments, prospect/contact
research, outreach playbooks, private analytics, credentials and unpublished
customer information outside this public repository. Do not copy them into PR
bodies, comments, screenshots, build logs, attachments or generated website assets.
A document without credentials can still contain private business information.

Before publishing:

- Verify capability claims against the source revision and released package or
  deployed service being described. Distinguish plans from available features.
- Check destinations, examples and citations. Preserve the limits of each proof,
  measurement and source; do not imply audit, partnership or customer validation.
- Inspect the staged diff and outgoing commits, not only the final file tree.
  Removing a private file at the branch tip does not remove it from earlier commits.
- Publish only reviewed project content to a verified project-owned destination.
  Keep personal accounts and raw internal reports outside automated distribution.

Internal commercial preparation documents previously committed to this repository
have been removed from the current tree. Their earlier public history remains;
this cleanup does not make previously published information confidential again.

# Proposed paid pilot: transfer evidence and exception review

Help a compliance operations team reconstruct why a transfer received a decision,
identify missing evidence and give an independent reviewer a portable record.
The first buyer hypothesis is a stablecoin processor or custodian already using
screening, Travel Rule and custody systems. Clearproof complements that stack.

## Buyer and problem to validate

A compliance/payments operations owner sponsors the work; a payments engineer owns
integration; a security reviewer approves data access; a named budget owner can
approve a continuation. These roles are hypotheses to confirm in interviews.

Start with one recurring job: reconstruct a transfer's evidence, diagnose a stuck
transfer, or assess a policy change. Establish its current frequency, operator
time, sources consulted and consequence of delay before discussing architecture.
Compare against the customer's existing logs and a small internal reporting script.
If that solves the problem adequately, stop or narrow the proposed integration.

## Proposed bounded engagement

A six-week measurement window begins only after agreed scope, approved test data,
access and operational owners are available. This is a planning envelope, not a
readiness or delivery-date promise. Proposed scope is one tenant, one read-only
source integration, one transfer workflow, one reviewed policy and one reviewer
export procedure. Changes require a revised scope and cost estimate.

| Stage | Customer contribution | Reviewable result |
| --- | --- | --- |
| Baseline | Authorized synthetic or controlled historical cases; existing workflow owner | Predeclared cohort and measured current process |
| Local replay | Approved source/policy mappings and expected labels | Coverage, outcome, disagreement and scoped latency report |
| Investigation | Example duplicate/reordered/missing events | Separate policy, exchange, custody and settlement states with next actions |
| Evidence review | Independent reviewer trust configuration | Encrypted bundle export and scoped offline verification result |
| Decision | Budget owner reviews operational evidence | Continue, revise or stop with an explicit reason |

For the local product demonstration, data and counterparties are synthetic and
keys have development assurance. Customer-connected observation needs F4 access,
permissions and an agreement. Live production authorization remains gated by F5;
this offer does not replace a compliance program, certify legal sufficiency,
execute payments, guarantee settlement or supply audited production proving keys.

## Current capability boundary

The draft source includes policy comparison, read-only investigation, authenticated
current proof inspection/evaluation, durable observations and cohort reports,
and encrypted evidence export/offline historical review. Real development proofs
and tenant/restart checks exist. The complete clean-environment pilot, deterministic
bilateral scenario, current authorization API and contract parity remain unfinished.
Managed connectors, supported hosting, retention operations and an SLA are proposed
services, not released products. Consult the implementation plan before each demo.

## Free foundation and proposed paid service

| Free distribution target | Proposed paid operational work |
| --- | --- |
| Verifier and portable evidence/report formats | Managed deployment, approved upgrades and operator support |
| Local policy simulator and synthetic counterparty tools | Connector setup, mapping, monitoring and refresh operations |
| Local inspection and offline review | Collaborative policy review and retained approval history |
| Exportable records | Reconciliation workflow integration and managed encrypted evidence preservation |

A reviewer must be able to inspect exported supported formats without a paid API
subscription. Do not make correctness or an ALLOW result a billable entitlement.
Packaging/public access still need their release gates; the table describes the
intended distribution boundary, not current public availability of every item.

## Continue only with evidence

Agree baseline and target values using the worksheet before running the cohort.
Useful evidence includes less analyst time for the same task, fewer unresolved
exceptions, successful independent evidence review and repeated operator use.
Keep missing cases, disagreements, errors and manual intervention visible.
A useful demo is not a purchase commitment: ask the budget owner for a scoped paid
continuation, procurement next step and decision date. A signed engagement and
repeat use, not a generated report, establish commercial progress.
